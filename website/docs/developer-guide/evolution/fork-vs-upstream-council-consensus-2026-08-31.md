**Дата:** 2026-08-31
**Вхідний аналіз:** [fork-vs-upstream-analysis-2026-08-31.md](fork-vs-upstream-analysis-2026-08-31.md)
**Формат:** незалежна панель `consult --panel` (радники не бачили одне одного), потім зведення голосів.

Продукт, про який домовилися: **самоеволюційний агент, який лишається нормальним щоденним чат-агентом**. Еволюція — ідентичність форку, але вона не має красти токени, квоту, увагу каталогу скілів і бюджет ходу в користувача.

## Про що домовилися

### 1. Два класи робіт, не один гейт

Суперечність R1 («не реєструвати LLM-джоби без GitHub write») і R4 («локальна інтроспекція не потребує GitHub») знята так:

**Клас A — роботи з виходом у GitHub**  
(research, issues, analysis, implementation, integration, PR-reflection, hydra-диспетчер, що відкриває issues/PR)

- Не запускати LLM, якщо автентифікований акаунт **не має push** на `Lexus2016/hermes-agent-evolution`.
- Read-only токен = немає write. Це вже є в `scripts/evolution_access_gate.sh` і лишається останнім рядком `{"wakeAgent": false}`.
- Додатково: такі джоби **не реєструвати** (або паузити вже зареєстровані), якщо write **підтверджено відсутній**. Інакше вони щодня цокають, навіть коли агент ніколи не прокинеться.

**Клас B — локальні роботи без GitHub**  
(introspection по власних сесіях, watchdog без LLM, дешеві no_agent скани)

- **Не** прив’язувати до GitHub write. Інакше інтроспекція помре саме на установках без токена — там вона найкорисніша.
- Окремий `evolution_local_gate.sh` (або еквівалент): немає нового локального сигналу → `{"wakeAgent": false}`, токени не їдуть.
- Дайджест інтроспекції винести з гілки «write confirmed» у `evolution_access_gate.sh` (зараз він там і через це вбиває R4).

`evolution/detect_mode.py` сьогодні бреше: немає токена → `PUBLIC` і `create_issues: true`. Третя станція: **OFF** (немає токена / немає write) / PUBLIC (write є, без merge) / PRIVATE (owner merge).

### 2. Реєстрація: три стани, не два

Поправка Claude (підтримана логікою Cursor: не дублювати перевірку, використовувати той самий write-check, що й гейт):

| Стан | Дія реєстратора на `hermes update` |
|---|---|
| Write підтверджено | реєструвати LLM-джоби класу A за chat-safe розкладом |
| Автентифіковано і **точно** відмовлено (403/404 на валідному токені) | **не** реєструвати клас A; уже зареєстровані — **пауза, не видалення** |
| Невизначено (немає `gh`/`curl`, мережа впала, rate-limit) | **не чіпати** поточний стан |

Fail-closed на невизначеному стані під час офлайн-`hermes update` зірве весь пайплайн власника. Watchdog (без LLM) може лишатися завжди.

### 3. Інтернет-ресерч не щодня

Власник: не частіше ніж раз на 5–10 днів. Рада: **раз на 7 днів** як дефолт у цьому діапазоні, інтервал — `evolution.research_interval_days` (5–10).

- `evolution-research`: не `30 9 * * *`, а щотижневий (наприклад `30 9 * * 1`) або еквівалентний інтервал.
- `evolution-issues`: **не** окремий щоденний LLM. Прокидається лише якщо є свіжий research-batch; порожній/застарілий batch → дешевий `no_agent` preflight, `wakeAgent: false`.
- Правило 7 днів стосується **web-research LLM**, не no-LLM перевірок на кшталт upstream-sync «чи вийшов новий release».

Без push у наш GitHub цей ресерч — марна трата токенів. Гейт класу A це закриває. Щоденний інтернет при наявному write — теж заборонений цим пунктом.

### 4. Dense cadence — лише явний opt-in

Hydra кожні 30 хв і analysis/implementation кожні 4 год — для **окремого owner-бота**, не для машини щоденного чату.

- Дефолт: `evolution.cadence: chat-safe` (ресерч ~тиждень, PRIVATE-пайплайн щонайбільше раз на день).
- `evolution.cadence: dense` — лише явний запис у `config.yaml`.
- Наявність `GITHUB_PRIVATE_TOKEN` на ноутбуці **не** вмикає dense.
- Реєстратор на кожному `hermes update` перезаписує `schedule` з YAML (`register_evolution_cron.py` reconcile). Opt-in має жити як YAML-overlay (`schedule` vs `schedule_dense`, вибір за `evolution.cadence`). Інакше апдейт мовчки зітре ручний розклад.

Codex хотів ще `evolution.enabled: false` навіть при write. Це **не** прийнято: власник хоче еволюційний агент, не вимкнений за замовчуванням. Chat-safe cadence замінює цей запобіжник.

### 5. Якість щоденного чату їде в тому ж пакеті (R6 не «фаза 2»)

Усі четверо: якщо змінити лише cron, користувач **нічого не відчує** в чаті. R6 — не прикраса.

**(a) Каталог скілів.** Дев’ять `evolution-*` не показувати в дефолтному чат-каталозі. Cron-сесії й далі резолвлять їх за ім’ям у `skills:` джоби. Тест: каталог чату = 0 `evolution-*`; `cron.jobs.create_job(skills=[...])` усе ще знаходить скіл.

**(b) Self-review-до-10.** Прибрати ритуал «оціни 1–10 і крути, доки не 10» з інтерактивного дефолту. Для evolution/cron сесій блок можна лишити. Патерн уже є: `TQMEMORY_GUIDANCE` інжектиться лише за умови. Це не новий prompt-блок (R7).

**(c) Spiral cap.** Не просто «підняти 5 → 10»:

- `per_tool_failure_caps`: `read_file: 10`, `search_files: 10`; `terminal`/`patch` лишаються на 5; `memory: 3`.
- Порожній, але коректний `search_files` **не** є failure.
- `_SUCCESSES_TO_DECAY = 1` для read-only інструментів (інакше fail → `pwd`/`ls` → fail накручує cap; Agy + Claude).

### 6. Що свідомо не робимо

- Нових core tools і нових always-on блоків у system prompt немає.
- `architecture_router`, `task_decoupling`, `experience_injection`, `agent_judge` тощо **не вмикати**, «щоб еволюція стала розумнішою».
- Не переписувати ядро Hermes.

### 7. Узгоджений follow-up, не блокер цього пакету

Усі четверо окремо вказали: `loop_guard` / refusal-nudge інжектять synthetic `role: user` і ламають prefix-cache. Це шкодить щоденному чату, але виходить за R7 (не нова інфраструктура в цьому пакеті). **Наступний крок після цього пакету:** замінити інжект на cache-safe механізм (спостереження в tool-result / існуючий stall-notice), не блокувати R1–R8.

`repo_map` у schema кожного виклику — теж follow-up, не цей пакет.

## Зауваження ради (окремо від домовленості)

Це те, на чому наполягали радники як на ризиках, навіть якщо пакет приймуть.

1. **Гейт write уже є, але його недостатньо.** Він ріже LLM. Він не ріже реєстрацію, каталог скілів і щоденний тік. Користувач без push усе одно носить дев’ять evolution-скілів у чаті.
2. **Інтроспекція сьогодні прив’язана до write-гейту.** Якщо «немає GitHub → не будити нічого», локальне навчання з власних сесій зникне. Рада вважає це помилкою.
3. **Реєстратор стомпить розклад** на кожному `hermes update`. Будь-який cadence opt-in поза YAML→registrar — мертвий.
4. **Порожній search як failure** робить підняття cap косметикою. Без цього пункта агент усе одно здається рано на розвідці репозиторію.
5. **Dense не виводити з типу токена.** Owner-токен на ноутбуці щоденного чату інакше знову з’їсть квоту hydra’ою.
6. **R6 не відкладати.** Cadence рятує гроші офлайн; чат платить на кожному повідомленні за self-review, cap=5 і evolution-скіли в каталозі.
7. Codex: не будити evolution-LLM, поки йде активний чат / ті самі креденшали. Рада не зробила це блокером; рекомендовано як наступне після пакету (окремий профіль або defer).

## Порядок впровадження (коли скажуть робити, не зараз)

Цей документ — домовленість, не патч.

1. Три стани реєстратора + split гейтів (GitHub vs local) + `detect_mode` OFF.
2. Chat-safe YAML-розклади + `evolution.cadence` overlay, щоб update не стомпив.
3. Research 7 днів; issues від batch.
4. Сховати `evolution-*` з чат-каталогу (із тестом).
5. Прибрати review-until-10 з інтерактивного промпта; підняти exploration caps і виправити empty-search / decay.
6. Follow-up: cache-safe loop_guard, схема `repo_map`.
